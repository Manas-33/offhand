# Offhand

Offhand is an Android assistant for small everyday tasks. Say "text Mom I'm on my way" or "set a timer for ten minutes" and it turns the request into a real phone action. The language model runs on the phone's own NPU, so it keeps working in airplane mode, and nothing happens until you approve it.

## What it does

Ask in your own words and Offhand picks one of ten actions and fills in the details.

| Action | You might say |
|---|---|
| Alarm | "Wake me up at 6:30 in the morning" |
| Timer | "Give me a timer for 45 minutes" |
| Reminder | "Remind me to call the dentist tomorrow" |
| Calendar event | "Put lunch with Sam on my calendar for noon today" |
| Text message | "Text Mom I'm on my way" |
| Email | "Email Priya that the report is ready" |
| Settings | "Open bluetooth settings" |
| Music | "Play some jazz" or "skip this song" |
| Flashlight | "Turn on the flashlight" |
| Note | "Make a note that the wifi password is on the fridge" |

Every action goes through a review sheet first. Texts and emails open as drafts in your messaging or email app, so you always press send yourself. When a request doesn't match any action ("what's the capital of Peru?" or "order me a pizza"), the model is trained to answer in plain text rather than force an action.

The release build does not request internet access. There is no server and no account.

## How it works

```
voice or text
  → fixed prompt listing the ten actions
  → Qwen3-0.6B, fine-tuned, 4-bit weights, running on the Hexagon NPU
  → <tool_call>{"name": "draft_sms", "arguments": {"recipient": "Mom", "body": "I'm on my way"}}</tool_call>
  → review sheet
  → Android intent or native call
```

1. **Listen.** Android's speech recognizer turns speech into text. You can also type.
2. **Understand.** The request goes into a fixed prompt that describes the ten actions (about 1,150 tokens) and runs through Qualcomm's GenieX runtime on the NPU. Decoding is greedy, so the same request always gets the same answer.
3. **Parse.** The app reads the streamed tool call and maps it to a concrete Android action.
4. **Review.** A sheet explains what will happen in plain English and shows the full text of any draft.
5. **Act.** On approval the app fires the matching intent (clock, calendar, messaging, email, settings, media search, share to notes) or a native call for the flashlight and media keys.

The app is Flutter on top of a Kotlin bridge. The prompt the phone sees is generated by the same code the evaluation uses, so on-device answers can be compared token for token with the GPU runs.

## Speed on the phone

Measured on a Galaxy S25 Ultra (Snapdragon 8 Elite), 4-bit weights and 16-bit activations (W4A16), with the full prompt:

| Model | First token | Generation | Model size |
|---|---|---|---|
| **Qwen3-0.6B, fine-tuned (Offhand)** | **283 ms** | **53 tokens/s** | **0.76 GB** |
| Qwen3-1.7B | 409 ms | 37 tokens/s | 1.76 GB |
| Qwen3-4B | 876 ms | 20 tokens/s | 3.18 GB |

The 4B model is also tight on the phone's 12 GB of memory and heats it noticeably, which is a big part of why Offhand uses the smallest model and fine-tunes it instead.

## Training

The model is Qwen3-0.6B fine-tuned with LoRA, with Qwen3-4B labeling the training requests. The data combines templated requests for each action, general questions that need no action, and a harder set: questions phrased like commands and routed to 24 extra tools that exist only in training, near misses, and requests no action covers. Three of the ten actions are left out of training entirely to test whether the model can use an action from its description alone. All training data is checked for overlap against the held-out test set in [eval](eval) and against BFCL.

## Running it

### Requirements

- A phone with a Snapdragon 8 Elite. Offhand is built and tested on a Galaxy S25 Ultra, and model bundles are compiled per chip.
- Flutter (Dart 3.11 or newer), Android Studio, and adb.
- A compiled model bundle. Model weights are not included in this repository.

### The app

The app loads a GenieX (qairt) bundle from its private storage at `files/models/Qwen3-0.6B-Specialist`: the QNN context binaries, tokenizer, `genie_config.json`, and a `geniex.json` manifest. Bundles are made with Qualcomm's `qai-hub-models` quantize and export flow and compiled on Qualcomm AI Hub. To place one on a debug build:

```bash
adb push Qwen3-0.6B-Specialist /data/local/tmp/
adb shell run-as com.offhand.offhand sh -c 'mkdir -p files/models && cp -r /data/local/tmp/Qwen3-0.6B-Specialist files/models/'
```

Then build and run:

```bash
cd app
flutter run
```

To work on the interface without a model, swap `GenieEngine` for `MockEngine` in `MainActivity.kt`. The mock streams canned answers for all ten actions.

### The evaluation

Check the harness with a mock model, no download needed:

```bash
python eval/run_eval.py --dry-run
```

Score a model on the test set (GPU recommended):

```bash
pip install -r eval/requirements.txt
python eval/run_eval.py --model Qwen/Qwen3-0.6B --config fp16 --data eval/phone_eval.jsonl --label my_run
```

`eval/run_device_eval.py` runs the same questions on a connected phone through a debug-only screen in the app. See [eval/README.md](eval/README.md) for the scoring details.

### Tests

```bash
cd app && flutter test
python eval/tests/test_harness.py
```

## Limitations

- **Voice input is not yet pinned to on-device recognition.** The model never needs a network, but the app uses Android's system speech recognizer without requiring its offline mode, so on a connected phone Android may process audio with its own online service. Typing always stays on the device.
- **One action per request.** "Set an alarm and text Sam" only does one of the two.
- **English only.**
- **Snapdragon 8 Elite only** for now, since bundles are compiled for a specific chip.
